# 运维、完整备份与异地同步

入口：左侧“服务”下方的“运维”。原 `/ops-center` 重定向到运维的“任务记录”，原有定时计划和 Agent 后台任务可在该页展开。

## 完整备份的范围与成立条件

每次选择容器后，预检会自动扩展到同一 Compose 项目名及工作目录下的所有容器。备份范围包括：

- 整个项目目录、原始 Compose / override / env / secret / config 文件及可解析的外部构建目录；保存最终 Compose 模型。
- 实际 bind 目录和单文件，以及实际命名卷、匿名卷。GNU tar 保存数字 UID/GID、权限、ACL、扩展属性、稀疏文件和链接元数据。
- 每个精确原镜像的离线归档；停机后通过 Docker commit 保存每个容器的可写层镜像，包含修改和删除信息，不用只导出基础镜像冒充可写层备份。
- 完整容器 Config、HostConfig、网络、卷定义、挂载映射及运行依赖清单。

只有预检通过、原运行容器全部干净停止、所有归档与镜像保存成功、AES-256-GCM 解密读回校验通过，并恢复原有启停状态及健康检查后，才原子写入 `receipt.json`。没有该收据或 `complete != true` 的目录不是已完成的完整备份，不能被同步任务选中。

原有“数据卷备份”只备份命名卷，保持原含义，不属于此处的完整备份。

## 使用步骤

1. 在宿主机创建独立备份目录，例如 `/vol1/1000/backups/composeops`，在“备份记录”保存默认目录。每次确认页也可修改保存目录并重新预检。目录必须已存在、可写、空间足够，不能与备份源重叠。
2. 在“容器运维”选择容器，点击备份或更新，核对关联容器、具体挂载、预计数据量和停机影响。没有历史测量时不显示虚构的停机分钟数。
3. 下载并单独保存恢复密钥，确认停写窗口。恢复密钥不写入备份或同步产物。
4. 提交后由独立 worker 容器运行，关闭页面不会取消任务。备份期间拒绝面板对同项目的并发修改；外部宿主进程和客户端仍需使用者协调停写。
5. 在“任务记录”查看阶段和结果。文件校验通过不等同于应用及数据库已经通过恢复演练。

点击任一容器的“更新”会自动覆盖其所属的**整个 Compose 应用**，确认页列出全部容器。完整备份成功后，统一拉取全部服务的现有镜像标签并强制重建；原运行服务一起启动，原停止服务只重建、不启动，最后核对原启停状态及健康。不自动修改标签或跨主版本升级。任一服务使用固定 digest、本地构建或禁止拉取策略，都会阻止整个应用更新并说明原因，仍可单独完整备份。独立容器、多副本服务需要先补齐明确的 Compose 更新方案。

发起更新或备份预检时，本页会暂停镜像检查并显示准备进度。预检只等待所选应用的工作区命令释放（最长 35 秒），不因无关应用检查而失败，也不会强杀正在运行的命令。等待超时仍明确拒绝，避免与配置操作并发。

## 镜像检查与列表

进入容器运维后自动按应用检查镜像，优先读取一小时内的成功结果，失败仅缓存 30 秒；代理、Compose 镜像来源或容器镜像 ID 变化会使缓存失效。“重新检查镜像”强制访问镜像仓库。最多同时检查三个应用，每个应用完成后立即显示结果，不等待整批结束。单应用后端限时 30 秒，浏览器 35 秒兜底；超时或仓库错误显示原因并支持单项重试，也可停止本轮检查。镜像检查只读，不拉取镜像或重建容器，检查期间仍可发起完整备份。

“代理设置”允许配置 HTTP/HTTPS 代理，留空为直连；“测试连接”验证 Docker Hub、GHCR 的授权及镜像清单读取，不保存配置；“保存并重新检查”持久化配置并使旧结果失效。容器访问宿主代理可使用 `http://host.docker.internal:7890`，部署 Compose 需配置 `extra_hosts: ["host.docker.internal:host-gateway"]`。此代理仅影响面板镜像查询及匿名仓库授权；实际拉取仍使用 Docker daemon 自身的网络设置，不改变 AI 或网盘同步的网络。代理地址不能包含认证信息或路径。

支持 `latest`、隐式 latest、Compose 变量展开、Registry v2 Bearer 匿名授权及多平台清单。按运行容器的精确镜像 ID 与当前平台远端 config digest 比较，兼容通过加速仓库拉取的镜像；不会把已经改变指向的本地标签当成容器实际运行版本。仅有本地镜像 ID 的服务明确标为本地镜像；固定 digest 标为锁定版本。image 与 build 并存可做只读比较，但实际更新仍需要明确拉取或构建策略，不暗中修改 Compose。

列表恢复紧凑布局：容器及当前镜像、所属应用分层展示，更新状态与运行圆点在同一格上下排列。默认只显示“可更新”“已是最新”“本地构建”等简短状态，点击状态可查看检查时间、具体原因并重试失败项。长镜像名称单行省略，完整值可在详情中查看；窄屏采用分层行布局，状态靠右，无需横向滚动。镜像检查比较当前标签内容，不提供未经验证的下一版本号。

未纳管、未授权目录或缺少 Compose 定义分别提示原因。本地构建、固定 digest 不会被当成“已是最新”。面板临时辅助容器默认隐藏，可勾选显示；辅助容器及面板自身排除批量操作。全选只作用于当前搜索列表中的可操作容器，操作按钮保持完整横排。

## 明确阻止的范围

当前执行支持 Linux 本机 Docker 节点；SSH/TCP 节点不会使用本机同名路径。以下情况会明确拒绝，不能静默排除并声称完整：

- 面板自身、辅助工作容器、Swarm、AutoRemove、暂停/重启/死亡状态。
- 未纳管或未授权目录的 Compose 项目、未部署服务、无法展开的文件引用和缺失路径。
- 数据被范围外容器共享写入、外部卷驱动 / NFS 等卷选项、应用 tmpfs、socket / FIFO / 设备文件。
- 过宽目录、Docker 内部数据目录、备份路径与源重叠、范围内包含备份恢复密钥。
- 源路径本身经过符号链接、指向范围外的符号链接、无法在同一归档中保留的外部硬链接。
- 停止超时被 SIGKILL、OOM、非零退出或备份后健康状态未恢复。

Docker socket 只记录为恢复时必须提供的运行依赖，不当作持久文件归档；设备映射也需目标主机提供。NAS 操作系统整机镜像不在应用备份范围内。

worker 临时只读递归挂载宿主根目录用于识别实际路径与读取被选中的数据，另外挂载只读数据卷及可写备份目的目录；不把宿主根目录写进部署 Compose。宿主需支持 Docker 的递归只读 bind mount。备份 worker 禁用外部网络，只通过 Unix socket 调用 Docker。

## 密钥及任务持久化

默认目录为数据库同级的 `maintenance/`，可用 `MAINTENANCE_DATA_DIR` 指向另一个持久挂载目录：

- `recovery.key`：随机 32 字节 AES 密钥，权限 0600。既用于备份加密，也用于保存同步凭据；不可覆盖、丢失或提交版本库。
- `catalog.json`：任务、备份及目标元数据；同步密码和 115 令牌只存密文。

每个备份批次保存加密产物、恢复日志及完成收据。失败中断不产生成功收据。停止前先持久写入需要恢复的容器 ID；正常失败逐项恢复。worker 异常丢失时任务标记待核对，可显式点击“恢复原运行容器”；该操作不写回备份数据。

## 115 官方直连

在“同步”添加 115 目标，配置自己的 [115 开放平台](https://open.115.com/) Client ID 和远端目录，然后在面板中扫码并在 115 App 确认。此处使用官方设备码 PKCE 授权，不采集 115 密码，不使用第三方网关或借用其他应用 Client ID。

令牌加密保存，按到期时间刷新；上传按官方 Open API 初始化并用 OSS 分片传输。只有网盘目录中的实际文件 SHA1 与长度均匹配，才报告该文件成功。没有真实应用 Client ID 和账号授权时，协议测试通过不能视为实际 115 验收。

接口依据：[115 Open API 文档](https://www.yuque.com/115yun/open)、[设备授权参数参考](https://github.com/OpenListTeam/115-sdk-go/blob/main/auth.go)、[上传接口参数参考](https://github.com/OpenListTeam/115-sdk-go/blob/main/upload.go)。

## WebDAV 与自动同步

配置服务地址、用户名/应用密码和远端目录，先测试上传及远端校验，成功后可手动同步指定完整备份，或开启“备份成功后自动同步”。使用 HTTPS 可保护认证及传输；不跟随跨站重定向发送密码。

备份完成并恢复应用后才上传，避免网络耗时延长备份停机窗口。每个目标按节点和批次建立目录，保留本地副本，不删除远端旧文件。WebDAV 下载读回 SHA256 校验全部内容；115 使用网盘文件 SHA1 和大小校验。失败保留部分上传和本地备份，可幂等重试；同名但不同内容会失败而不是覆盖。测试会在 `.connection-tests` 目录留下小型测试文件。

## 隔离解密与恢复验证

```bash
node backend/scripts/full-backup-extract.js \
  /path/to/backup-batch \
  /separate/location/composeops-recovery.key \
  /new/isolated/output
```

脚本校验密文摘要、GCM 标签以及加密恢复清单的一致性，全部成功后才保留新的隔离输出目录；拒绝覆盖已有目录，不写回原应用，不启动容器。输出中的 `manifest.json` 和 `RECOVERY.md` 描述原容器、数据映射和镜像快照，用于隔离 Docker 环境的恢复演练。

实际恢复界面的路径/卷重映射和冲突确认仍需另行实施。不能把“已解密”说成“已恢复应用”，也不能把模拟 Docker 驱动测试说成 NAS 上的真实恢复验收。
